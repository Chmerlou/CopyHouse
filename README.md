# CopyHouse

Веб-платформа-агрегатор печати. В репозитории сейчас каркас бэкенда дня 1: NestJS на JavaScript, PostgreSQL, схема Prisma и проверка `GET /api/health`. Авторизация, загрузка PDF и заказы — следующие дни спринта.

Исходники лежат в `backend/src` и написаны на JavaScript. При сборке Nest прогоняет их через компилятор: декораторы вроде `@Controller` и `@Get` сам Node не понимает. TypeScript писать не нужно.

## Что нужно

- Docker и Docker Compose
- Для локальной разработки без контейнера API: Node.js 22+

## Поднять всё одной командой

Из корня репозитория:

```bash
docker compose up --build
```

API: http://localhost:3000/api/health

Ожидаемый ответ: `{"status":"ok"}`. При старте контейнер применяет миграции Prisma.

PostgreSQL снаружи: `localhost:5432`, база `copyhouse`, пользователь `copyhouse`, пароль `copyhouse`.

## Локальный запуск API

Поднять только базу:

```bash
docker compose up postgres -d
```

Дальше в `backend/`:

```bash
copy .env.example .env
npm ci
npx prisma migrate dev
npm run start:dev
```

## Проверки

```bash
cd backend
npm run lint
npm test
```

## Схема базы

Деньги хранятся в копейках. Файл PDF на диске появится вместе с загрузкой; каталог `uploads` уже предусмотрен томом Docker.

- `users` — email, хэш пароля, роль `CLIENT` или `PARTNER`. У партнёра заполнен `pickup_point_id`, у клиента — нет. Снаружи регистрация партнёра не откроется: учётки точек приедут сидом.
- `documents` — владелец, имя, путь, mime, размер, число страниц.
- `pickup_points` — название, адрес, часы строкой, ставка ч/б и цвет, комиссия в базисных пунктах (`1000` = 10%), флаг активности.
- `orders` — клиент, точка, статус `CREATED | PAID | PRINTING | READY | ISSUED`, снимки страниц и ставки, сумма, комиссия, итог, код выдачи.
- `order_items` — одна позиция заказа: документ, режим печати, копии, цена строки.
- `payments` — мок-оплата, один платёж на заказ.

Клиент платит цену печати. Комиссия удерживается из этой суммы и сохраняется в заказе.
